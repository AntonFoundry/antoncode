# Agent Note: WM 缓冲区填满其窗口
[English](2026-09-01-wm-buffer-fill-guarantee.md) | 中文


Status: implemented

[English](2026-09-01-wm-buffer-fill-guarantee.md) | 中文

## Problem

Emacs 风格窗口管理器中，缓冲区并不填满其窗口。一个切换到 Workspace 缓冲区的窗口（关闭主侧栏窗口后 C-x b）在 1600×449 的窗口里只渲染出 288×260 的小盒子，其余全部空白。两个独立成因：

1. `WmFrame` 的窗格包装层把任何显示 `sidebar` 缓冲区的叶子固定为 `flex: 0 0 ${width}px`。在纵向分割里该基准作用于竖直轴，窗格被钉成 288 像素高；而且在主左栏之外的任何位置，钉定的像素值都与窗口实际槽位无关。
2. `SidebarRoot` 展开时自设内联 `width`（owner 传入的栏宽像素），因此即使窗口更宽，缓冲区也无法伸展超过栏宽偏好值。

即便修掉这两处，框架右缘仍留有一条死区：小于 1 的 flex-grow 因子只分配该比例的剩余空间（sub-one flex-factors 规则），因此钉定侧栏（grow 0）旁边聊天的存储权重 `0.8` 只填了剩余宽度的 80%。因此包装层的 grow 按该分割未钉定权重总量重新归一，保持 Σgrow 恒等于 1；附带效果是钉定侧栏旁的边界拖拽现在 1:1 跟随指针（此前边界只移动指针增量的 grow 比例）。

第三个缺陷放大了症状：c0ntext 插件每次启动（rAF 延迟）调用 `ctx.layout.openDetails()`，违背 ui-layout 自己「Context 初始关闭」的决策重新分割聊天窗口，并在每次 reload 后重新对抗用户的关闭手势。同时 `onSplit` 会静默拒绝分割（只要屏幕上已有 Context 窗口，聊天窗格上的 `C-x 2` 就是空操作）——分割规则聚焦到已存在的 details 叶子而不是分割。

## Decision

- 像素钉定只作用于它本该作用的那个窗格：主侧栏窗格 —— 规范 sidebar 叶（`WM_LEAF_SIDEBAR`）作为横向分割的子节点（`isHomeSidebar`）。其余所有窗口无论显示什么缓冲区都按分割权重（`flex: W 1 0%`）排布，因此填充链（treeArea → split → paneWrapper → pane → paneBody → 缓冲区根）对每个缓冲区/窗口组合都成立。
- 边界拖拽遵循同一谓词：只有触及主侧栏窗格的边界写宽度偏好；脱离原位的 workspace 窗口边界改写普通分割权重。
- `SidebarRoot` 填满其窗口：展开时无内联宽度（根节点伸展；为保证成立显式声明 `width: 100%`）；内联宽度仅保留为收起淡出的冻结上次展开宽度。
- `C-x 2`/`C-x 3` 永远分割，新窗口显示锚点自身的缓冲区：缓冲区是内容，窗口是查看它的视图，单例与其他缓冲区一样可以克隆（两个 Chat 窗口是同一会话面的两个视图；注册表中每种缓冲区仍只有一个）。此语义取代了过渡期的配对规则（聊天 → Context，否则 `*scratch*`），而后者又取代了更早的静默空操作。
- c0ntext 插件去掉启动时的自动展开；映射图通过顶栏开关或 `c0ntext:open-map` 恢复控制打开。

## Alternatives considered

**完全移除像素钉定（全部用权重）。** 拒绝：侧栏宽度偏好（store 持久化的像素值、拖拽钳制契约）是既定的几何契约；主栏必须跟踪它，而不是权重比。

**在 `buffer === 'sidebar'` 上保留钉定并让 SidebarRoot 响应式取宽。** 拒绝：纵向分割里钉定基准的方向就是错的轴；组件层修复救不了方向错误的 flex basis。

**按工作区（而非每次启动）自动打开一次上下文映射。** 拒绝：任何自动 `openDetails` 都会在 reload 后重新对抗用户的关闭手势；按需打开是已记录的布局决策（Context 初始关闭）。

## Consequences

- 缓冲区在任何位置都填满其窗口；在已部署应用中端到端实测（1600 像素窗口中的 workspace 缓冲区填满 1600 像素）。
- 聊天窗格上的 `C-x 2` 把聊天克隆进第二个窗口；`C-x b` 是克隆而非抢焦点，`C-x ←/→` 循环整个注册表、不再跳过已在别处显示的缓冲区。
- 启动加载为 Workspace | Chat；上下文映射按需打开。
- 持久化树在加载时只做权重重归一化——单例去重与强制关闭 Context 已移除，因此排布好的布局（含刻意的克隆）按原样重载。
