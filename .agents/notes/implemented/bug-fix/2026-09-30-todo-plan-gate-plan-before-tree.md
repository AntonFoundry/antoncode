# Agent Note: Plan recorded before the todo tree grows past the gate threshold

Status: implemented

English

## Problem

The `todo-plan` gate denies execution tools once the session's todo tree counts `minTodosForImplementationPlan` (default 3) items and no `plan/write` event exists, but the working-discipline prompt taught the opposite order: "write a todo tree with todo_write FIRST", and only then — via a subagent that authors a comprehensive implementation plan — record the plan. A session following the prompt literally built a 3+ item tree, hit the gate on its first `bash`, and could recover only if the plan-authoring subagent succeeded; in deployments where `subagent` delegation fails, the session stalled between a gate demanding a plan and a prompt whose only path to a plan was the failing subagent. The gate's denial text repeated the same delegation-first teaching, and the `todo_write` and `subagent` prompt sections carried it too.

## Decision

The canonical order is unconditional everywhere the model reads it — plan first, record the plan, then the tree, then execute:

- `TODO_TREE_DISCIPLINE` (`@deepseek-ai/dsh-tools`) mandates recording the plan with `plan_write` BEFORE `todo_write` whenever the work is non-trivial (3 or more tasks, multi-phase, cross-package, or architectural), and states the resilience rule: the plan never waits on delegation — a failed or unavailable subagent is not a blocker, and the plan is authored inline from current knowledge and recorded.
- The `todo_write` description carries the same order in its head, workflow step 1, and persistence paragraphs.
- The `subagent` prompt section stops presenting delegation as the path to the plan: exploration is delegated to draft the plan, and inline authoring replaces a failed delegation.
- The gate's implementation-plan denial teaches the plan-before-tree order and the inline fallback instead of delegation-first. `subagent` and `plan_write` remain never gated, so the fix path is always executable.

This amends the workflow ordering of [subagent implementation plans](../feature/2026-09-18-subagent-implementation-plans.md), which still owns the gate mechanism, `plan_write`, and the split-buffer presentation.

## Alternatives considered

- **Raising the gate threshold so small trees never block**: rejected — it weakens the plan-first discipline the gate enforces and only moves the collision to larger trees.
- **Delaying the denial until several gated calls fail**: rejected — the gate's value is denying before the first mutation, and a delayed denial still lands mid-flight with the same prompt contradiction.
- **Auto-satisfying the gate when `subagent` fails**: rejected — the gate reads the session log deterministically; teaching the model the always-executable fallback (author inline, record with `plan_write`) keeps the mechanism simple.

## Consequences

Sessions cannot deadlock between the prompt and the gate: any tree at or past the threshold has its recorded plan before the tree exists, so execution tools never deny on a tree the prompt itself instructed the model to write. Delegation stays preferred for context preservation but is no longer load-bearing. The cost is prompt length — the discipline section names the full order and the fallback explicitly.
